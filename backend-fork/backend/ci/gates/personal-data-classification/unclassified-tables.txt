# Personal-data classification: this gate's declared, shrink-only backlog.
#
# THIS IS NOT THE ONLY BASELINE, AND SINCE 2026-08 IT IS NOT THE DECISIVE ONE.
# The other check, `every_application_column_is_classified_or_its_table_is_declared`
# in backend/crates/platform/db/tests/personal_data_classification.rs, reads the
# catalog of a migrated database and carries its own baseline as Rust data. That
# baseline used to pin each table's unclassified COLUMN COUNT; it now names the
# per-table SET of unclassified column NAMES -- 247 tables, 2,621 names.
#
# WHY THAT MATTERS TO THIS FILE. A count is payable. Classify one existing column
# in the same migration that adds an unclassified one and the number does not
# move, so the catalog side saw nothing and only this gate's parser stood in the
# way. Six rounds of hardening that parser each closed one spelling and each was
# followed by another; every one of those escapes was that same composite. A SET
# has nothing to pay with: adding an unclassified column makes the set gain a
# name, classifying one at the same time makes membership move, and both fail
# there regardless of how the DDL was spelled.
#
# So for any relation the catalog sweep reads, a blind spot in this parser no
# longer composes into a silent live unclassified column. That is a statement
# about the composite, not about this parser, and it stops where the sweep stops.
# WHAT IT EXCLUDES, named rather than implied:
#
#   * relations created at RUNTIME, which are in no migration text and in no
#     catalog built from ./migrations. This already ships: 0005's
#     location_pings_ensure_partition() creates a day partition per day, and the
#     ten classified columns of the parent prove nothing about the child.
#
# The former relkind/schema divergence against personal_data_columns() is
# closed: migration 0211 now uses this same non-pg_catalog, non-temporary
# ('r','p','m','f') universe and returns schema-qualified identities. PostgreSQL
# tests plant non-public, materialized-view, and foreign-table markers and
# require each to reach the retention derivation.
#
# This file is what the text parser sees; that one is what PostgreSQL holds.
# Today this file names 242 tables and the catalog's names 247. The five it has
# that this one does not are the five no migration in this tree creates:
# `_sqlx_migrations`, which sqlx creates, and the four real tables PostgreSQL
# ships in `information_schema` -- sql_features, sql_implementation_info,
# sql_parts, sql_sizing -- which entered that sweep when an unexplained
# `nspname <> 'information_schema'` predicate was deleted from it. Every table
# this file names, the catalog's names too. They are allowed to diverge further:
# the parser has named blind spots (see the crate doc in src/lib.rs), and the
# catalog does not parse anything.
#
# Every table listed here has at least one column with no personal-data
# classification. Listing a table here is an admission that nobody has
# classified it yet -- it is NOT a statement that the table holds no personal
# data, and nothing derived from the classification can be assumed to cover it.
#
# THE RATCHET, AND HOW IT IS ENFORCED RATHER THAN ASSERTED. A table may only
# leave this list, never join it. Three checks make that true, and appending a
# line to this file trips one of them whatever you write:
#
#   * a listed table that is now fully classified   -> remove it
#   * a listed table that no longer exists          -> remove it
#   * a column introduced AFTER migration 0209, in a listed table -> classify
#     it; the entry does not cover it
#
# The third is the one that closes appending. The gate has no memory of the
# previous version of this file -- CI checks out a single commit with no
# history, so there is nothing to diff against -- and migration numbers supply
# the missing clock instead. Every table not listed here today is fully
# classified, so naming one trips the first check; a name matching nothing trips
# the second; and a genuinely new table, or a new column on a listed one, trips
# the third. See BASELINE_FROZEN_AFTER_MIGRATION in src/lib.rs.
#
# That property -- not this file's length -- is what makes THIS list a ratchet.
# It is kept as defence in depth for the one thing the catalog cannot do: this
# gate sees a column at WRITE time, before any database exists, in milliseconds,
# on a developer's machine. Bounded, measured parser corrections can strengthen
# that early edge; the catalog's name-set assertion remains the independent
# control rather than depending on this parser becoming complete.
#
# Generated by `cargo run -p console-gate-personal-data-classification --
# --inventory`, i.e. by the same parser that enforces it. A hand-maintained
# second inventory would be free to disagree with the gate about what a column
# is.

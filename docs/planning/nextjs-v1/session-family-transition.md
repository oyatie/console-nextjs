# Live session-family binding

Scope: the next foundation requirement of R4, following current-authority validation. Root is the sole implementation writer in the independent fork. Base is the frozen source HEAD `05200e43af13b527ce031b04369e05852862f1d6` plus the accepted deltas identified by `fork-delta.json` SHA-256 `e573636e7eb7dabd41bc595f6ae53d526b2a10431b7003fd30f30667735024f8`. Original Console is untouched.

Observed gap: logout and refresh reuse revoke `auth_refresh_token_families`, while the shared access validator only checks account generations. The same already-issued access JWT can still act after that family's revocation. No new session database or workflow engine is needed: the existing family owner and Company RLS already hold the authoritative revocation state.

Implementation contract:

- Ordinary access JWTs carry an additive signed `session_family_id`. The shared request validator requires an existing, unrevoked family bound to the exact account and home Company, in the same scoped query as current account/version validation. Missing, foreign, revoked or unavailable family authority fails closed. This applies to tenant, platform and credential/self-service requests and WebSocket handshakes.
- Initial login issues the real refresh family before minting its access JWT. Refresh keeps the existing family identity. Issuance and rotation retain `family_created_at` in their existing result type; access expiry is bounded by the configured access TTL, that refresh token's expiry and the existing absolute family deadline. Rotation at or after the absolute boundary fails closed. After acquiring the token/family locks, evaluate time again using at least current wall-clock time (never earlier than the supplied request time); lock waits cannot extend either token or absolute expiry. No access JWT extends that deadline.
- Delegated `actor_session` additionally carries the validated original family ID and source access expiry. Group/platform mint paths copy these values from validated source claims, and the issuer clamps child expiry to the source expiry. JWT verification uses zero expiry leeway and explicitly requires `exp > now`; delegated source expiry must also exceed current time and contain the child expiry. Issuance rejects an already expired source/deadline, including exact equality. Validation rejects conflicting bindings. Revocation during child mint cannot create a fresh family or extend the original source lifetime. Target Cedar freshness remains unchanged.
- Logout revokes only the selected family through its existing owner. Other active families remain usable. Refresh-token reuse invalidates both old and newly issued access JWTs in that family. There is no cache of cross-request allow decisions and no browser token-storage change in this step.

Compatibility: old access JWTs lacking a family binding decode for inspection but cannot establish a runtime session; clients use their existing valid refresh cookie/token to obtain a bound access token. No passkey, Account, Person, refresh token, family, Company or migration is reset. Legacy delegated contexts are reminted from a bound source. Existing JWT signing helpers remain useful for codec tests, but unbound signatures grant no runtime access. Do not add a test-only authentication bypass or a production legacy fallback. Existing integration fixtures must establish a real family; retain their behavior assertions. This work is not a deployed cutover or authorization to run mixed old/new auth servers; old servers cannot enforce this boundary and are not a safe rollback.

Proof: real PostgreSQL through a non-owner/non-BYPASSRLS pool; two independently issued families for one account; actual refresh/logout HTTP handlers; exact old access JWT denial after logout/reuse; sibling-family survival; missing/wrong account/wrong Company/unknown family; current credential routes; delegated home-family revocation and revoke-during-mint; near-boundary lifetime clamps, exact and sub-60-second expiry, lock-delayed rotation crossing the absolute deadline, and legacy-refresh continuity. Preserve existing passkey, JWT, current-authority, target Cedar, view-as and tenant isolation assertions. Record discovered/executed/ignored counts and fixture corrections. Tests that only verify a JWT signature do not prove a live session.

Pre-mortem: an unbound compatibility path would silently retain the original defect; a freshly read or newly created family during delegation would renew revoked authority; unconstrained child/access expiry would exceed source or absolute lifetime. Detect all with exact-token replay and controlled PostgreSQL lock interleavings. Blast radius is the auth/refresh/request-context owners, direct mint callers, and authentication test fixtures. No schema migration or destructive contraction is planned. Rollback must preserve family revocations; reverting to an unbound validator is unsafe.

Limits: request-boundary checks do not serialize a later domain write with concurrent revocation, prevent every concurrent primary-authentication/recovery race, or revalidate an already-open WebSocket. Those remain required subsequent owner work. Two-site confirmation, server-only browser sessions, scoped platform support, actual human proofing and complete business workflows remain unaccepted. This record does not reduce the full plan.

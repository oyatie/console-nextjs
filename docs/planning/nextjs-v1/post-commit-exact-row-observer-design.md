# Post-commit exact-row observer — proposal

Status: **proposed, unimplemented, not approved for serving**. Source base: independent `backend-fork` `fccad07eafa0d39189f42effaf08ac7f1e3ab06f`. This is a bounded PostgreSQL observer slice, not a writer lease, acknowledgment gate or release receipt.

## Source boundary

`backend/crates/platform/db/src/durability.rs:81–190` already captures one post-COMMIT primary WAL **INSERT-LSN** and checks primary flush and a directly queried physical standby's flush/replay through caller-supplied pools. Its `ExpectedWriter` is caller-supplied; the database epoch marker in migration `0236_platform_durability_epoch.sql` is intentionally empty after installation. The disposable physical test uses two localhost PostgreSQL processes and manually inserts epoch 7. No serving code calls the observer. `audit_tx.rs:86–92,129–137` returns after COMMIT, and `app/src/lib.rs:3815–3820` correctly reports `write_ready=false` without fencing writes.

The next source change belongs **only** in `platform/db/src/durability.rs` and its physical test. Add a distinct `AuditedRowCustody` result for one caller-generated audit ID and exact Company, action, target type and target ID; it must not implicitly convert to the generic `ConfirmedWalPrefix` or authorize a business acknowledgment. On the identified primary, use a fresh READ COMMITTED transaction with transaction-local Company RLS context to query and match that committed row; then capture **one** primary `pg_current_wal_insert_lsn()` upper bound after the row check. Hold that bound fixed while requiring primary flush plus independent standby flush and replay at or beyond it. Query the same exact row on the standby in a new READ COMMITTED transaction with its own transaction-local Company context after replay, then recheck topology, timeline and epoch before returning the original INSERT bound. Absent, ambiguous or changed evidence is an error or pending/UNKNOWN; neither a primary-only row nor a successful COMMIT is confirmation. The observer's Company GUC scopes a query but does not itself confine an infrastructure credential to one Company.

Do not copy the isolated `f8c29c5` candidate as-is. Its physical test passed 1/1, but its audited path substituted an initial FLUSH bound and a final standby replay LSN for the required post-COMMIT primary INSERT bound. A primary audit SELECT can emit hint-bit WAL. Capture after that SELECT and keep the captured INSERT bound immutable through polling **and retry**. On timeout, return UNKNOWN with an opaque pending observation containing that same bound and exact row/topology/epoch identity; an in-process continuation must wait on the same bound. Do not recapture, lower or replace it with FLUSH/replay. This bounded slice has no durable custody for the pending observation: after process loss, cross-process retry remains unsupported and UNKNOWN until a separately reviewed recovery design exists. Prove quiet-WAL liveness without changing the bound. Do not wire `with_audit`, HTTP, reads, Office, outbox or mail to this limited custody result yet: an audit row alone does not authenticate a business receipt, current authorization or external-effect owner.

## Executable red probe and proof

There is **no current red lane** for this exact-row slice on clean `fccad07`; the existing physical test is green. First make a test-only isolated lane extending `backend/crates/platform/db/tests/durability_physical.rs` with the new exact-row API call. It must fail on the clean source, then pass on the exact candidate. Reuse the existing disposable harness with this command from `backend-fork`:

```sh
RUSTUP_TOOLCHAIN=1.98.1 PG18_BIN=/opt/homebrew/opt/postgresql@18/bin \
  bash backend/crates/platform/db/tests/run-durability-physical.sh
```

The test must assert exact Company/ID/action/target mismatch denial; no result during paused standby replay or canceled `SyncRep` waiting despite a locally committed row; eventual confirmation after replay; and returned prefix at or beyond an observed post-COMMIT primary INSERT bound, including a quiet-WAL/hint-bit case. Force a timeout, continue the **same** pending observation and prove the bound is unchanged; process loss must yield an explicit UNKNOWN/unsupported continuation, never a fabricated confirmation or silent new bound. The harness may use a superuser to configure the disposable cluster, but the audited-row checks must execute through a non-owner, non-BYPASSRLS observer role on both connections; test Company A's context cannot read Company B's row. RLS alone does not authorize that observer to choose a Company, so production cross-Company credential custody remains a separate prerequisite. Keep the original bound observable to the test without permitting callers to forge a confirmed prefix. Record exact discovered/executed counts, hashes, peer review, and the pre-mortem before integrating. A compile-only missing-symbol failure is insufficient to validate the bound semantics.

## Physical blockers, risk and rollback

The localhost harness does not prove two independent full sites, production TLS/credential custody, distinct buildings/power/network, compatible Apple x86 standby build/collation/extensions, a current monotonic etcd writer/egress lease, positive old-process/network fencing, safe read-prefix certificates or recovery clone. `ExpectedWriter` plus the replicated marker cannot mint those facts. Test actual site loss, partition, stale sender, timeline change, dropped COMMIT response, operation reconciliation and credential revocation before any confirmed response or external effect. `write_ready` stays false and live reads/egress remain unactivated.

Blast radius of this proposal is the dormant observer and disposable test. Roll back by discarding the isolated source/test patch; do not alter applied migration bytes or accepted records. If an exact-row check advances the WAL bound without demonstrable liveness, or if a reviewer must replace INSERT with FLUSH/replay to make the test pass, stop and revise the design. Meaningful observer implementation can proceed with disposable physical instances; serving use cannot proceed without the independent-site and fencing evidence above.

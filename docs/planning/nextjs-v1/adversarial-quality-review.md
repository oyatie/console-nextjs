# Adversarial quality review of existing surfaces

_2026-09-27. Scope: inspect and mature the routes, components, controls, and workflows already present. This is a QA method and a set of probes, not a claim that the product passes them._

Start with one real user task. Record its route, visible control text, input contract, handler, authoritative mutation owner, observable result, failure path, and test evidence. A control is complete only when the result survives the boundary it promises: a toast, screenshot, simulated click count, or browser-state mutation does not prove a saved business operation. Run the same task with valid input, invalid input, a stale record, a different Company or role, an interrupted request, and keyboard-only interaction. Fix the first broken ownership or interaction boundary, then repeat on its sibling callers.

The current boundary matters. `src/app/(console)` mostly reads and mutates seeded `src/lib/store.ts` state, while the public storefront calls a Rust backend through `src/app/storefront/api.ts`. The [implementation checkpoint](IMPLEMENTATION.md) explicitly marks full release acceptance as failed or unreached. The existing `tests/ui-workflows.test.ts` manually records clicks and changes the store; it is useful prototype logic evidence, not proof that a person can complete those clicks in the rendered UI or that a server committed them. Treat the console's role selector and cryptographic-looking audit display as prototype behavior until an actual session, server authorization, and durable owner are connected.

## What the online evidence supports

Sources below were fetched on 2026-09-27. The research motivates probes; it does not diagnose this repository by itself.

| Source | Verified point | Limit |
| --- | --- | --- |
| [Stack Overflow 2025 Developer Survey, AI section](https://survey.stackoverflow.co/2025/ai/) and [methodology](https://survey.stackoverflow.co/2025/methodology/) | Among respondents to its AI-frustration question, 66% selected solutions that were “almost right, but not quite”; 45.2% selected AI-generated code taking longer to debug. | Self-reported, multi-select answers from a survey recruited mainly through Stack Overflow channels; not a measured failure rate for this app. |
| [Perry et al., *Do Users Write More Insecure Code with AI Assistants?*](https://arxiv.org/abs/2211.03622), CCS 2023 | In studied security tasks, access to a Codex-based assistant led to less secure submissions and greater belief that the code was secure. | Specific participants, tasks, and an older model; no estimate of present-day defect rates. |
| [Pearce et al., *Asleep at the Keyboard?*](https://arxiv.org/abs/2108.09293), IEEE S&P 2022 | About 40% of 1,689 generated programs were vulnerable in 89 security-focused Copilot scenarios. | Deliberately security-focused scenarios and a 2021-era tool; do not generalize the percentage to all generated code. |
| [GitHub Copilot responsible-use guidance](https://docs.github.com/en/copilot/responsible-use/inline-suggestions) | GitHub warns that plausible generated code may be incorrect or insecure and tells users to review outputs against requirements. | Product guidance, not an independent measurement of this codebase. |

| [OWASP Top 10:2025, Broken Access Control](https://top10.owasp.org/2025/A01_2025-Broken_Access_Control/) | Changing a URL, internal state, or API request can bypass presentation-only checks; authorization must be enforced on the server and on the record. | A risk category and test basis, not proof of a vulnerability here. |
| [web.dev Web Vitals](https://web.dev/articles/vitals) | Loading, interaction, and visual stability are measured through LCP, INP, and CLS; recommended good thresholds are 2.5 s, 200 ms, and 0.1 at the 75th percentile. | Production field metrics are needed for a real user-performance claim. |

## Existing-surface QA matrix

| Surface already here | Adversarial probe | Evidence required to call it mature |
| --- | --- | --- |
| Shared controls: `Button`, `DataTable`, `ConsequenceModal`, route-specific action buttons | Inventory every visible button and icon with its label, enabled condition, handler, state transition, and result. Try double click, disabled state, cancel, callback failure, and stale data. In `DataTable`, the sort-looking arrows have no sort handler, and the paste banner reports success immediately after calling `onPasteRows`; test whether those signals match actual behavior. | Each apparent affordance performs its named task or is clearly non-interactive. A success message follows a verified outcome; failed or uncertain results are distinct. The same control behaves consistently wherever reused. [NN/g](https://www.nngroup.com/articles/ten-usability-heuristics/) |
| Fields in `MoneyInput`, people onboarding, attendance, approval drafts, and `InquiryForm` | Enter empty, zero, limits, pasted commas, negative and decimal values, full-width digits, ambiguous dates, malformed references, and Korean IME composition. Submit with one bad field after completing all others. `MoneyInput` currently strips every non-ASCII digit, shows `required` only as a star, and renders a separate label with no programmatic association to its input: verify its intended input contract and accessible name. | Unit, date meaning, permitted precision, and actual object choice are clear before submission; specific field errors preserve the rest of the draft. Server and preview rules agree. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) [WAI forms](https://www.w3.org/WAI/tutorials/forms/validation/) |
| Approval, HR action, and payroll commitment in `approvals/page.tsx`, `hr/actions/page.tsx`, `hr/payroll/page.tsx` | Start with a different Company, wrong person or period, changed source data, duplicate submit, and an interrupted response. Check the consequence preview against the resulting authoritative record; cancel before commit. Compare draft, submitted, approved, paid/exported, and corrected states. | The screen names the subject, legal employer, period, reviewer, and exact consequence before commitment. Cancel leaves no mutation; a final outcome is never inferred from a display-only confirmation. Legal or financial data can be reviewed and corrected before finalization. [WCAG 3.3.4](https://www.w3.org/TR/WCAG22/#error-prevention-legal-financial-data) [NN/g](https://www.nngroup.com/articles/ten-usability-heuristics/) |
| Console role and Company selection, governance, and mutations in `src/lib/store.ts`; transport guard in `src/lib/server/mutation-guard.ts` | Change `viewAsRole` or `activeEntityId`, modify record IDs and direct requests, use a revoked session, and cross Company boundaries. Test the server owner, not just what a button hides. The guard itself says it only checks transport provenance. | Every read and mutation resolves a live identity, Company, permission, and record scope on the server; denial changes no data and leaks no protected fields. Until the console is wired to that owner, label these workflows prototype-only. [OWASP A01](https://top10.owasp.org/2025/A01_2025-Broken_Access_Control/) |
| Drafts and receipts in `src/lib/store.ts`, payroll, and storefront inquiry | Reload, open another browser, edit concurrently, lose the network response after a possible commit, and retry. The storefront currently reports its receipt as pending or uncertain because there is no status lookup or idempotency key; verify that text remains truthful and a retry cannot be advertised as safe. | A “saved” claim has durable server acknowledgment; a lost response leads to status lookup or an explicit uncertain state, not duplicate work. Reopening restores the exact draft and exposes concurrent edits. The console browser store cannot currently satisfy a durable business claim. [NN/g](https://www.nngroup.com/articles/ten-usability-heuristics/) |
| Keyboard, screen reader, and narrow layout across `DataTable`, `ConsequenceModal`, search, and dense payroll screens | Navigate with Tab, Shift-Tab, Enter, Escape, and a screen reader; test 320 CSS px and 400% zoom. `DataTable` attaches J/K key handling to `window` and its search uses placeholder text without a label. `ConsequenceModal` has no dialog semantics or focus management in its component. Check that shortcuts do not act while focus is elsewhere and that errors and async status are announced. | Every action is reachable without a pointer; focus enters and exits dialogs predictably; controls have names; blocking errors and result states are announced; critical context remains visible on narrow screens. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) |
| Code and test ownership for each completed flow | Trace rendered control → handler → validation → owner → durable result → audit/recovery. Compare the rule in preview, client, server, and tests; challenge copied conditions and dead props. Then exercise the rendered task and a failure path in a browser test. Run typecheck and the focused owner tests. | One accountable owner defines the business rule. Tests fail when the actual flow breaks, rather than merely replaying a hand-written click script. Remove duplicate or decorative code only after the real flow is understood. [GitHub guidance](https://docs.github.com/en/copilot/responsible-use/inline-suggestions) [Stack Overflow survey](https://survey.stackoverflow.co/2025/ai/) |
| Data-heavy tables, payroll, and storefront pages | Use a realistic record count, slow network, and mid-range mobile device. Check task completion time, search delay, table responsiveness, and layout shifts; collect LCP, INP, and CLS when real traffic exists. | The task remains operable while loading; no false “empty” state or blocked input. Field metrics meet the published thresholds at the 75th percentile before making a production performance claim. [web.dev](https://web.dev/articles/vitals) |

This matrix is intentionally tied to existing surfaces. New UI or framework abstractions should follow a demonstrated failure in one of these flows, not an assumption that another layer will make the app mature.

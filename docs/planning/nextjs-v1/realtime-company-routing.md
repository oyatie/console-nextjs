# Realtime Company routing

Base: candidate `7104338cf61601bf532f37befe39380f773f83c145779a37a37b93b5d129fcdb`, preserved in `.artifacts/candidates/`. Root is the sole implementation writer. The original Console, historical migrations and all existing assertions remain unchanged.

Observed defect: the realtime hub selects message recipients by branch scope and thread membership, and notification recipients by user ID, without matching the connection's Company. The same natural account can have delegated connections in several Companies. `BranchScope::All` and a globally unique user ID do not establish Company authority. Notification delivery additionally trusts the recipient ID supplied in `pg_notify` instead of binding it to the fetched canonical row.

The existing hub owns fan-out. Extend that owner without a new router, provider or authorization engine:

- Require `slot.principal.org_id == publishing_org` both when collecting message membership candidates and when selecting message/ack targets. Preserve branch scope, actual thread membership, bounded queues and replay behavior.
- Carry the publishing Company through notification fan-out. Match both the Company and the canonical row's recipient to the connection. If the wake payload's recipient disagrees with the fetched notification, return an error before delivering anything. The payload is a wake hint, never authority to redirect a notification.
- Keep message and notification fetches under the existing Company-armed runtime RLS owner. Message lookup already binds both message and thread IDs. Test mismatched thread IDs and forged Company IDs through real PostgreSQL notifications; neither may cause delivery.
- Update the existing test-only notification dispatcher to take Company and derive the recipient from its supplied summary, eliminating the redundant redirect parameter. It is not a production admission path.

Acceptance: preserve all inherited hub, payload and PostgreSQL bridge tests. Add deterministic hub tests with the same user connected to two Companies with `BranchScope::All`, covering posted messages, acknowledgment counts and notifications; assert exact delivery in the owning Company and no queue entries in the other. Add live PostgreSQL bridge tests through a non-owner, non-BYPASSRLS runtime role for canonical notification recipient routing, forged recipient, forged Company, and mismatched message/thread identity. Use bounded waiting and a real listener barrier to avoid treating an unprocessed wake as proof of denial. Capture failing tests before implementation and rerun exactly those tests afterward. No production records or provider success are fabricated.

Pre-mortem: filtering only candidates misses preauthorized/test paths; filtering only message posts misses ack/notification metadata; trusting wake payload recipient redirects canonical content. Detect with identical actors and unrestricted branch scopes across Companies, and hostile real notifications. Blast radius: realtime hub and its focused tests only. Rollback restores only this candidate's edits and does not modify schema, queue history, identities or sessions; the insecure prior path cannot be exposed while rollback is in place. Stop on any weakened assertion, unexpected delivery or regression, and return to independent review.

This correction does not complete ongoing WebSocket session/scope/object revalidation, owner field/purpose policy, safe replay cursors, Matrix E2EE, two-site confirmation or release acceptance. Those remain mandatory under R4. Current data already sent to a browser cannot be recalled.

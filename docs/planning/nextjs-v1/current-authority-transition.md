# Current authority before authenticated SSR

The saved R4 plan requires current authority and immediate revocation across API, SSR and realtime. The frozen request-context owner verifies JWT signatures and reloads branches/custom grants, but ordinary token roles and session generations do not currently require a live active account. The platform extractor does not consult PostgreSQL at all. Authenticated self-service and group-administration routes have separate signature-only helpers.

Scope: close that shared authentication gap before wiring the Next frontend to authenticated business APIs. Preserve JWT formats, passkey identifiers, migration checksums, Company RLS, existing role policy and endpoint contracts. No deployment or new institution authority is granted.

Use one shared live-claims validator in the request-context owner. Under a transaction armed to the proven account's home Company, require an existing active account, the expected home Company, and matching subject/session generations. Ordinary token roles must remain a subset of current account roles; adding a new role never expands an old token. Current object and field policy still runs at the consuming owner. Signature failures, missing authority and unavailable storage fail closed.

Apply the validator to tenant HTTP/realtime principal resolution, platform principal resolution, authenticated passkey/consent/device operations and group-administration actor resolution. Platform principals still do not arm a business Company context. Delegated Group tokens validate their home account independently from the target Company and retain the existing live Group grant check. Delegated tokens require an additive signed `actor_session` claim (home Company, subject version, session generation); legacy delegated tokens without that binding require reauthentication. No cross-Company account search or default-home fallback is introduced. View-as tokens validate the real platform operator and retain the existing read-only gate. Existing platform impersonation and action-approval policies remain unaccepted against the full R4 product; this change does not certify those broader controls.

Token minting preserves existing target subject/policy/session freshness fields for Cedar compatibility and separately binds `actor_session` to the real account's home. Group delegation must match its existing home claim; platform delegation must bind the platform sentinel and match the existing read-only view-as or writable SUPER_ADMIN shape. Platform direct sessions must use the sentinel, an active account, signed SUPER_ADMIN and current stored SUPER_ADMIN, with the same token-role subset check. Every tenant request, including delegated/view-as, separately requires an ACTIVE target Company. The sentinel organization is intentionally archived and is not a business Company. Ordinary tenant sessions require an ACTIVE Company. Delegated minting copies generations from the already validated source token, never a newer database read that could silently renew a concurrently revoked session. This prevents a revocation in the home Company from being missed because no account row exists in a target Company. Authenticated self-credential operations reject delegated/view-as contexts. Legacy tokens remain accepted only when their current authority can still be proved; otherwise the client must authenticate again without resetting credentials or identities.

Verification: add a red PostgreSQL integration target using signed tokens, actual owner writes and a non-owner/non-BYPASSRLS runtime pool. Exercise active account success, inactive/missing/cross-Company subjects, role removal/addition, subject/session changes, platform revocation, delegated home revocation and authenticated credential endpoints. Run affected existing auth, platform/group and freshness suites; fix fixtures where they never established a real account, preserving behavior assertions. No mocked provider-success acceptance. These checks prove the authorization boundary, not a human passkey ceremony or two-site durability.

Risk: a stale token could retain privileges or a delegated actor could be checked in the wrong Company. Detect with negative requests using the exact pre-revocation token. Blast radius: shared request-context and its direct authentication/mint callers in the independent fork. Rollback restores code only; it must not restore revoked data/credentials. The old code would reopen the demonstrated authorization gap and therefore is not a safe production rollback. No contraction or schema rewrite is involved. Stop on unexplained contract/identity changes or failed required proof. Independent review and commands/results are recorded in reviews.json and the evidence index.

Base: frozen source HEAD `05200e43af13b527ce031b04369e05852862f1d6` plus the already reviewed install-lineage deltas. Original Console remains untouched.

Limits: request-boundary validation does not serialize a later domain transaction with concurrent revocation. Existing owner execution checks remain required, as do ongoing WebSocket revalidation, per-refresh-family access-token revocation and scoped platform support authority. Inherited platform delegation remains unaccepted against R4; preserving its token shape here does not authorize exposure. Old binaries ignore the additive actor binding and are unsafe for this authentication boundary after rollout; mixed-writer deployment is not approved by this patch.

Selected lenses: Red Team, Operability / Day-2, Blast-radius / cell-based and Zero-trust / defense-in-depth. Root is the sole implementation writer. The review candidate is identified by SHA-256 of these bounded files because this independent frozen workspace has no commit history; no upstream branch or release operation is performed.

Review regressions: target suspension after delegate mint denies the same token; later platform role elevation cannot expand an older MEMBER token; revocation between validation and child mint leaves the child at the original generation and rejected. Missing/mismatched actor bindings fail closed and target Cedar fields remain unchanged.

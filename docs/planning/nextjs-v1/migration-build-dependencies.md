# Native Cargo invalidation for embedded migrations

Base: accepted backend `2406ee701d5f8c75d9079931e50e209da070169944122077b0d15b398c7a9b38`. Root is the sole writer. This fixes the observed stale SQLx migration embedding on new SQL files; it changes no migration, runtime business behavior, database privilege, dependency version or production lockfile.

Pinned SQLx 0.9.0 uses `include_str!` for existing files. Stable Rust does not enable its conditional directory tracking. A new migration can therefore leave a previously built executable or test binary unchanged. The 0226 and 0228 verification histories record this actual failure; cleaning the build cache is a workaround.

Use one native `crates/platform/db/build.rs` to emit `cargo:rerun-if-changed=../db/migrations` and `cargo:rerun-if-changed=../db/baseline`. The database owner and authz packages are siblings. All other consumers rebuild through a normal or dev dependency on the database owner. Set authz's package `build = "../db/build.rs"` to cover its nine migration attributes without adding a circular dev dependency or changing Cargo.lock. No custom file walker/hash engine, nightly feature, global compiler flag or duplicated package scripts are needed.

Read-only grounding found 58 consumer packages across 175 workspace packages. All except authz have a database-owner dependency path. Notifications, registry, support, messenger, notices, platform, identity and inbox REST have direct dev edges; dispatch worker and leave REST have transitive normal edges. Production embedding is in the app's main and baseline installers. A conservative source/manifest census must reject any newly uncovered consumer; it does not stand in for executable tests.

Use real pinned SQLx/Tokio, fixture-only offline lock resolution starting from the preserved production lock, then locked offline builds with unchanged sources/manifests/script/lock/target across phases.

Warm the fixture and repeat without changes. Independently add, edit, rename and remove fixture migrations and add/edit/remove baseline SQL. Compare actual embedded version, description, SHA-384 and SQL with file-derived expectations. Real attribute tests run in disposable PostgreSQL, comparing applied ledger and SQL-created diagnostic values. Expectations arrive only as runtime environment values, never compile-time invalidation. Record Cargo JSON freshness and actual test/executable results; unchanged builds must remain fresh. SQL mutation happens only in disposable fixtures, never in the accepted source migrations or baseline. Preserve every original SQL and production lock hash before/after.

Selected lenses: Systems Thinking, Chesterton's Fence, Red Team, Operability and Essentialism. Pre-mortem: a missing dependency leaves one suite stale, a forced clean or source rewrite masks the bug, runtime expectations accidentally become compiler inputs, or the script rebuilds forever. Detect each through the graph census and fixed-source incremental fixture. Stop on changed production locks/migrations, uncovered consumers, failed positive/negative proof or a script that needs cache cleanup to work. Rollback retains the accepted source/binary/data; removing the watcher is not a safe way to build future migrations. No deployment or full R4 acceptance follows.

# Current authority at WebSocket emission

Base: accepted candidate `149348322c4a0fe4f0221519bca5e27f7403ecca6d66443bf16ed1092e269e1e`. Root remains the only implementation writer. Full R4, including current field/purpose rules, Matrix and two-site durability, remains mandatory and unaccepted.

Observed flow: the upgrade resolves current authority once, then discards the credential. A queue contains materialized message/notification summaries, which the socket serializes without further checks. Replay cursor lookup reads any same-Company message ID without proving membership. Account/family revocation, expiry, narrowed branches, removed thread membership and changed/deleted content after enqueue do not reliably prevent the old frame from being sent.

Use existing owners rather than another authorization cache or event engine:

1. Retain the original bearer only in the server socket task's memory. Never log, serialize, persist or include it in Debug output. Before preparing each queued or replayed data frame, invoke `resolve_principal_from_bearer_token` again. This reuses live family/account/Company/delegation/branch checks. No cached allow decision or unbound fallback is permitted.
2. Add an exact-message application query and implement it in `PgMessengerStore` using the existing actor-aware projection. Its single Company-RLS SELECT binds the message ID, current actor membership and supplied current branch scope. Missing/inaccessible rows return no content. Reuse its membership predicate in existing page/search reads so the final page SELECT checks membership rather than relying only on a preceding transaction. Keep existing HTTP status checks and pagination behavior. Bind reply-quote joins to the same thread and project the joined quote ID; corrupted cross-thread references expose neither ID, body nor sender name. Preserve valid same-thread quotes.
3. Add an exact-notification query to the existing notification owner. One RLS SELECT binds ID and the current recipient and uses its existing mute predicate and projection. This is recipient authority, not a claim that the inherited arbitrary body/link format implements all source/field/purpose permissions.
4. At socket dequeue, use only queued IDs/type as hints. Re-read via these owners under the freshly resolved Company. For messages and acknowledgments, require the canonical thread to match the hint, return current branch and current projected values, including actor-specific acknowledgment state. For notifications, require the canonical recipient. Never serialize the queued body, count, link or sender projection. Re-resolve identity after materialization and ensure the result is still in the live branch scope before emission. Denial, missing rows, identity drift or unavailable authority closes the connection with a generic policy/unavailable reason and emits no cached fallback.
5. Authorize the replay cursor through the exact-message owner before reading its timestamp. Keep existing bounded replay ordering/queue behavior and per-frame materialization. An inaccessible cursor fails closed; the client may explicitly reconnect without that cursor. Do not infer another user's cursor timestamp.
6. Bound preparation and socket writes (five seconds each). Bound the whole connection by the signed access deadline, including idle connections. Closing/lagging/replay-failed notices take priority over simultaneously-ready data, including while preparing or waiting to write. Own the spawned replay producer through an AbortHandle in the connection slot and abort it on every slot-removal path, including shutdown, lagging and self-disconnect; handle the spawn/handle-install race. Cursor/page read futures also have five-second bounds. Set transaction-local PostgreSQL statement_timeout to five seconds for the exact-owner and replay reads, so abandoning a client future cannot leave these server statements running indefinitely. SQLx future cancellation alone is not proof of statement cancellation. Shared current-principal resolution retains the serving role's existing thirty-second database limit: the socket stops waiting after five seconds, while its database cleanup may take up to that native bound. Always remove the connection after exit; do not hold the hub mutex across database or socket waits. Already handed-off bytes cannot be recalled, and a timed-out write is not proof the client received nothing.

The exact-message read is the membership/data snapshot; current account/family/scope is checked before and after materialization. This step is not an atomic transaction covering every authority source, the network and two-site confirmation. Revocation racing after the final observation, field/purpose/source-policy enforcement and the final writer/durability epoch still require the planned shared execution/emission boundary. Do not claim complete ongoing realtime authorization or release readiness from this candidate. No schema, passkey, session identity or external live operation changes.

Tests precede implementation and use real PostgreSQL/runtime RLS and actual loopback WebSocket frames. Preserve all inherited tests. Exercise successful current message/ack/notification delivery; queued family/account/Company/branch/thread revocation; current actor-specific projection and content reload; expired access, unavailable authority and an idle deadline; replay blocked while a revocation commits; inaccessible same-Company replay cursor; terminal close without draining buffered content; expiry/terminal notice while an owner query is blocked; revocation after the initial principal resolution but before materialization finishes; replay producer termination and native statement bounds; valid same-thread and invalid cross-thread quote projections. Deterministic queue probes acquire a test-owner lock on the refresh-family table after upgrade, enqueue through the existing hub path, apply a change, then commit. This blocks the future emission authority query without blocking existing message membership fan-out. Replay probes lock message reads before handshake and commit revocation before releasing the read lock. No sleeps stand in for evidence that a queue drained; use bounded frame reads and positive controls. Record exact discovered/executed/failed counts and distinguish fixture errors.

Pre-mortem: checking only periodically misses queued data; reusing cached summaries leaks corrected/removed content; accepting a cursor without membership reveals private ordering; duplicated projections drift from actor-aware owner values; slow clients hold resources; detailed close reasons disclose IDs. Detect through wire-level negative/positive controls and existing owner/browser-boundary tests. Blast radius: messenger/notification application read contracts and adapters, realtime emission/cursor code and focused tests, plus existing dependency promotion in Cargo metadata. Rollback is source-only and cannot expose the older unauthorized route; no migration or history rewrite. Stop on assertion weakening, owner bypass, deadlock, leakage or material design change and return to independent review.
